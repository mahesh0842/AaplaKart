📊 Database Schema

Tables (SQLite — auto-created):

users — uid (PK), phone_number, email, display_name, role, is_test_user
addresses — id (PK), user_uid (FK), full_name, phone, line1/2, city, pincode, lat/lon
orders — id (PK), user_uid (FK), status, subtotal, delivery_fee, total, payment_method, address snapshot...
order_items — id, order_id (FK), product_id, name, price, quantity, weight, image_path
shops — id, name, latitude, longitude, address, active
⚠️ Order status format: HYPHEN-SEPARATED (e.g. out-for-delivery)

🔌 WebSocket — Real-time Order Updates

📡 WebSocket Endpoint

ws://<host>:8000/ws/orders
Message Protocol:
Client → {"type": "ping"}
Server → {"type": "pong"}
Server → {"type": "order_update", "order_id": "...", "status": "...", "updated_by": "..."}
Server → {"type": "new_order", "order_id": "...", "status": "pending", "total": 250, ...}

🔧 WebSocket Manager

File: app/services/websocket_manager.py
Features:
• ConnectionManager class — tracks all active WS connections
• broadcast() — sends message to ALL connected clients
• broadcast_to_role() — sends to specific user roles
• connect/disconnect — track client lifecycle

Events that trigger broadcasts:
• Order status change → "order_update" event
• New order placed → "new_order" event
